# 文章结构模板（aolun-attack 引用）

> 供 `aolun-attack/SKILL.md` 使用。写完第一层诊断（矛盾定位）后，按文体/篇幅选定一个结构，照此组织正文。结构类型同时写入「输出规范」的元数据。

## 结构一：标准攻击文（适合技术评论）

```
矛盾定位：[2-3句，写作框架声明，不计入正文字数]

第一节：问题的提出（50-100字）
  [引用原帖的核心主张，不加评论，让读者自己先读到]
  [提出一个悬念：这个主张是否真的成立？]

第二节：概念解剖（200-400字）
  [这个东西真正是什么]
  [定义里藏了什么]
  [概念和历史上的先辈们]

第三节：机制与约束拆解（300-500字）
  [因果链的哪里断了]
  [真实条件下会发生什么]
  [被刻意隐藏的边界条件]

第四节：利益与动机（100-200字）
  [谁在推这个，他们得什么好处]
  [信息选择背后的议程]

第五节：他山之石（200-400字）
  [真正的问题是什么]
  [其他领域是怎么解决这个问题的]
  [更好的方向在哪里——即转化条件（1.4）的展开]

第六节：结语（50-150字）
  [不是总结，是定性]
  [反讽的刀，一刀收尾]
```

## 结构二：快速评论（适合推文/短帖回复）

```
矛盾定位：[内部使用，不输出到正文]

第一句：复述对方核心主张（5-20字）
中间：一个最致命的弱点 + 一条具体证据（50-150字）
最后：一句有力量的定性（10-30字）
```

## 结构三：深度技术拆解（适合长文）

```
矛盾定位：[2-3句，作为引言的前置框架]

引言：这篇文章要做什么
第一部分：解剖（四层全写）
第二部分：弱点清单（逐条列出，附依据）
第三部分：历史上的前辈（案例 + 结局）
第四部分：谁在推、为什么推
第五部分：更好的解法（跨领域方案，即转化条件的展开）
结论：这个东西的真实定位是什么，应该在什么场合用、什么场合不用
```

---

## 何时读取

- 写正文前：选定结构类型，照对应模板组织段落。
- 写完正文：回到 `SKILL.md` 的输出规范，附上文章元数据。
