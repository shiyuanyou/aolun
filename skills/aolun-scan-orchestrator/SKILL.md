# 扫描层并行编排器（按需）

> "兵贵神速，更贵合围。四面同时出击，对手连逃跑的方向都找不到。"
> —— 李敖

## 核心职责（按需调用，不是必经步骤）

本 skill 只在**需要全维扫描**（同时从逻辑 / 工程 / 历史 / 动机四个维度找弱点）时才被调用。**单维扫描不需要走本编排器**——直接调用对应的 `aolun-scan-logic` / `aolun-scan-engineering` / `aolun-scan-history` / `aolun-scan-motive` 即可，由主 agent 或调用方自行决定维度。

**何时调用本 skill：**
- 需要对一篇完整技术文章/方案做全面弱点扫描 → 四路全维。
- 只需要确认某个逻辑是否成立 → 直接调 `aolun-scan-logic`，不走本编排器。
- 只需要工程可行性、历史教训或深层动机 → 直接调对应单维 scan-*。

**关键原则：**
- 全维扫描时，四个扫描器 subagent 尽量在同一条消息中发出（真正并行扇出）；宿主不支持并行时按顺序执行并在产物中诚实记录。
- subagent 通过文件路径 / 摘要获取原文和上游输出，**不通过 prompt 粘贴文本内容**（内存模式仅为无法落盘时的降级）。
- 综合报告是唯一传递给下游的内容，四份 subagent 全文报告不进入主窗口。

---

## 输入来源判断

本 skill 有两种运行模式，取决于上游是否通过 fileflow 派发：

| 运行模式 | 判断条件 | 原文获取方式 | 上游输出获取方式 |
|---------|---------|------------|-------------|
| fileflow 模式 | 存在 `00-todolist.md` 和 `00-original.md` | 读取文件路径，subagent 自行搜索 | 读取文件路径，subagent 自行读取 |
| 内存模式（短文本） | 不存在上述文件 | 完整原文已在主 agent 上下文中 | 解剖摘要已在主 agent 上下文中 |

**fileflow 模式优先。** 如果检测到 fileflow 任务目录（通过 `00-todolist.md` 存在性判断），必须使用 fileflow 模式。

---

## 执行步骤

### Step 1：准备解剖层输入摘要

从解剖层报告中提炼（约 200 字）：**fileflow 模式**从 `00-todolist.md` 状态表摘要列和各步骤输出文件的 `【摘要】` 块提取；**内存模式**从主 agent 上下文的解剖层输出提炼。

```
【解剖层输入摘要】
概念层：[核心声称] + [最关键的概念漏洞 1-2条]
机制层：[声称的原理] + [因果链中最脆弱的环节]
约束层：[被隐藏的关键约束] + [边界外失效场景]
利益层：[主要推动方] + [信息选择偏差方向]
```

### Step 2：扇出四个扫描器（并行优先，顺序兜底）

**并行扇出：** 支持并行调用的宿主中，在同一条消息发出四个扫描器 subagent（真正并行）。

**顺序兜底：** 宿主不支持并行（如只能单步调用）时，按 scan-logic → scan-engineering → scan-history → scan-motive 依序执行，汇总方式相同。**无论并行还是顺序，都必须在产物中诚实记录执行方式**（见 Step 3「执行方式标注」）。

#### 统一压缩 dispatch 模板（路径/摘要 + 扫描器名 + 返回格式）

每个扫描器 subagent 的 prompt 统一为以下三要素，不再内联超长模板。搜索重点一律**回放各 scan-\* 自己的 SKILL.md**，本编排器不重复维护各维度搜索指令：

```
你是 <扫描器名>。使用 aolun-<扫描器名> skill 对目标文本做 <该维度> 扫描。

【输入】（只传路径，不塞原文；按运行模式取其一）
- 原始文件：<00-original.md 或源文件绝对路径>（fileflow 模式）
- 索引与状态：<00-todolist.md 完整路径>（fileflow 模式）
- 上游输出：<已执行的解剖层文件路径，如 01/02/03/04，缺失的不列>
- （内存模式）直接给解剖层摘要 + 完整原文（仅当无法落盘且 ≤8000 token）

【执行】
1. 按 aolun-<扫描器名> 的 SKILL.md 执行该维度完整扫描（搜索重点以该 SKILL 为准）
2. 每个弱点附原文行号 + 直接引用；搜索未果声明"未找到直接证据"
3. 报告写入：<扫描器报告路径或返回给主 agent>

【返回格式】
在报告末尾追加：
【致攻击层的摘要】（来自 <扫描器名>）
最致命的一击：[一句话]
弱点清单（最多5条，按攻击力排序）：
  1. [类型] — [原文证据，直接引用原句] — 攻击力：[高/中/低]
```

四个扫描器 = `aolun-scan-logic` / `aolun-scan-engineering` / `aolun-scan-history` / `aolun-scan-motive`；各维度的搜索重点、检查清单与输出差异均在对应 scan-\* 的 SKILL.md 中，此处不重复。

---

### Step 3：汇总综合报告

四个 subagent 全部返回后，从每份报告中提取 `【致攻击层的摘要】` 块，汇总为：

```
【扫描综合报告】
（由 aolun-scan-orchestrator 汇总，共4个维度）
> 执行方式：<并行 / 顺序>（本次实际执行的扇出方式，诚实记录）

逻辑维度最致命：[来自 scan-logic 的"最致命的一击"]
工程维度最致命：[来自 scan-engineering 的"最致命的一击"]
历史维度最致命：[来自 scan-history 的"最致命的一击"]
动机维度最致命：[来自 scan-motive 的"最致命的一击"]

全弱点清单（攻击力排序，去重合并，最多10条）：
  1. [弱点类型] — [维度] — [原文证据] — 攻击力：[高/中/低]
  2. [弱点类型] — [维度] — [原文证据] — 攻击力：[高/中/低]
  3. ...
```

**汇总规则：**
- 按攻击力（高→中→低）排序
- 同一证据被多个扫描器引用时合并为一条，注明多维度
- 超过10条时保留攻击力最高的10条
- **执行方式标注（诚实记录）：** 综合报告顶部标注本次是 `并行` 还是 `顺序`；若宿主不支持并行而采用顺序执行，必须写明「本次为顺序执行」。

**fileflow 模式下：** 将综合报告写入 `05-scan-summary.md`，并在文件顶部包含 `【摘要】` 块，执行方式标注一并写入。

### Step 4：收尾串行验证（Ownership Table / 文件级 single-writer）

并行（或顺序）扇出后，**收尾必须串行验证**，不能直接交付：

1. **文件级 single-writer：** 每个扫描器只写自己的报告文件（`05-scan-logic.md` / `05-scan-engineering.md` / `05-scan-history.md` / `05-scan-motive.md`），互不覆盖；综合报告只由本编排器（唯一 writer）写 `05-scan-summary.md`。同一文件不得被两个 subagent 同时写。
2. **Ownership Table（归属表）：** 记录每个产物的唯一属主，防止并行写冲突：

   | 产物文件 | 唯一属主（writer） |
   |---------|------------------|
   | `05-scan-logic.md` | scan-logic subagent |
   | `05-scan-engineering.md` | scan-engineering subagent |
   | `05-scan-history.md` | scan-history subagent |
   | `05-scan-motive.md` | scan-motive subagent |
   | `05-scan-summary.md` | aolun-scan-orchestrator（唯一汇总 writer） |

3. **串行验证：** 四个扫描报告全部落盘后，主 agent **依序**逐个核对其存在、非空、含 `【致攻击层的摘要】` 块与行号引用，再据此汇总综合报告；缺任一报告则补跑该扫描器后再汇总，不带着缺失继续。

## 向下游传递

**fileflow 模式：** 下游 skill 通过 `00-todolist.md` 获取综合报告路径。

**内存模式：** 综合报告直接传递给：
- `aolun-other-mountains`：工程弱点清单作为跨领域解法的需求入口
- `aolun-attack`：完整综合报告作为攻击文弹药库
