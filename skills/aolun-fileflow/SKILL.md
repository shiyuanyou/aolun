# 文件持久化分析路由器（fileflow）

长文本分析是持久战。不落盘，中间态就在 compact 里消失。

**主 agent 只做两件事：管 `00-todolist.md`、派发 subagent。**
**subagent 自己从文件系统读原文与上游输出，产出落盘。**
**主 agent 永远不把原文或上游内容塞进 prompt——只传路径 + 五段式任务卡。**

`00-todolist.md` 是唯一真相源：它含状态表、债区、原文索引。所有中间态与债都以它为凭，别的文件只是产物。

---

## Part 1：启动

1. **提取 brief**（规则以 `aolun-prepare-docs` 为唯一权威，不重复定义）：从前 50 字符生成任务目录名。
2. **检测已有准备**：任务目录已有 `00-prep-meta.md` 就读取输入形态/存储模式/搜索策略，跳过文档准备，直接建 `00-todolist.md` 并做崩溃恢复检测；没有则继续。
3. **建目录与准备**：文档准备以 `aolun-prepare-docs` 为权威，fileflow 只消费其结果或做最简内联兜底（粘贴文本存 `00-original.md`）。路径输入且无 `00-prep-meta.md` 时，提示先走 prepare-docs，终止。
4. **建 `00-todolist.md`**（格式见 Part 5）。头部写入 `> 授权模式：默认等人 / 无人托管`，默认「默认等人」。`00-prep-meta.md` 存在时从其读取搜索策略，否则用默认。
5. **崩溃恢复**：`00-todolist.md` 已存在 → 读状态表，从第一个 `⬜待执行` 恢复，问用户「继续 / 从头开始」。旧任务目录（只含旧编号文件、无债区）仍可读可恢复，债缺失不阻塞——恢复时把未闭合线索就地补记进债区，不强制迁移。
6. **选工作流**：展示菜单（见 Part 3），等人确认后开始。

---

## Part 2：派发与执行

### 核心分工

```
主 agent：管 00-todolist（状态 + 债区 + 摘要）→ 派发 subagent → 读落盘摘要 → 阶段结束停人
subagent：读 00-original / 上游输出 / 00-todolist → 执行 skill 分析 → 完整输出（含【摘要】+ 债回报）落盘
```

**禁止：** 把原文段落、上游输出复制进 subagent prompt（除非降级到内存模式）。

### 五段式任务卡（派发只传这个 + 路径）

每次派发用一张短任务卡，五段，不塞原文内容：

```
你是 aolun 分析管线的一环。执行 <skill> 分析。

【正目标】
本步要交付的单一可验收产出：<按 skill 定义的本步核心结果>。

【负目标 / 边界】
不做 / 不该出现：<不越层、不覆盖他人产出、不臆造证据、不写无引用结论、不与 01/02 重复展开>。

【前置依赖】
输入只读以下路径（只传路径，不塞原文）：
- 原始文件：<00-original.md 或源路径>
- 真相源：<00-todolist.md 完整路径>
- 上游输出：<上一步输出文件路径>（第一步无此项）
输出写入：<当前步骤输出文件完整路径>

【什么算够好】
验收标准：<核心清单达成、证据带行号 + 直接引用、未找到已声明「原文未找到（已检索全文）」、产出落盘且含【摘要】>。

【尚不知道什么】
写清你还没法验证的点，不假装知道；这些进【债回报】。

执行：先读 00-todolist 的索引/搜索策略/债区 → 用 Read/Grep 找关键证据（每条带行号 + 引用）→ 按 <skill> 的 SKILL.md 执行 → 完整输出写入指定路径。文件顶部含【摘要】（3-5 行核心判断），后接完整内容。

债回报（并入输出末尾）：新债 / 路线变化 / 需要主窗口决定。
```

**内存模式降级（仅无法落盘时）：** 宿主不允许写文件/读文件系统才允许把原文或产出塞进 prompt，并在 `00-todolist.md` 原文索引标注 `（内存模式）`；一旦可落盘即回到路径派发。

### 每步收尾

① 更新 `00-todolist.md` 状态：当前 `🔄当前` → 完成后 `✅完成`，写入摘要列。② 从输出提取【摘要】与【债回报】。③ 认下新债（先去重归并，见 Part 5；阻塞型需决定先暂停）。④ 展示摘要，不展示全文。⑤ 是否停下由 Part 4 checkpoint 决定，不每步停。

## Part 3：默认步骤表与工作流

默认步骤表（对齐 plan §7）：

```
01-dissect  →  02-scan  →  03-other-mountains（可选）  →  04-attack  →  99-final
```

**不再为四层/四维分别建文件，不再沿用旧的四层/四维步骤与输出名。**

### Workflow 1：快速狙击（落盘）

| 步骤文件 | 调用 Skill | 是否必须 |
|---------|-----------|---------|
| `01-dissect.md` | `aolun-dissect`（轻量：只概念+逻辑增量） | 必须 |
| `02-attack.md` | `aolun-attack`（快速评论，50-200 字） | 必须 |
| `99-final-<slug>.md` | — | 用户选择整合时生成 |

适合：只需要快速定位主要弱点，不做全面拆解。

### Workflow 2：标准拆解（默认，推荐）

| 步骤文件 | 调用 Skill | 是否必须 |
|---------|-----------|---------|
| `01-dissect.md` | `aolun-dissect` | 必须 |
| `02-scan.md` | `aolun-scan` | 必须 |
| `03-other-mountains.md` | `aolun-other-mountains` | 可选（执行前询问用户） |
| `04-attack.md` | `aolun-attack` | 必须 |
| `99-final-<slug>.md` | — | 用户选择整合时生成 |

适合：一篇完整的技术文章或方案。执行到 `03` 前问：`是否需要引入跨领域解法？[是/否]`。

### Workflow 3：底朝天全拆

同 Workflow 2，`02-scan.md` 之后增加：

| 步骤文件 | 调用 Skill | 说明 |
|---------|-----------|------|
| `02b-deep-verify.md` | `aolun-scan`（单维/深挖模式） | 仅证据不足维度触发，可选 |
| `03-other-mountains.md` | `aolun-other-mountains` | 可选 |
| `04-attack.md` | `aolun-attack` | 必须 |

适合：重要行业论断或主流方法论。深度验证仅在证据不足时触发，证据充分则直接通过。

### 选择参考（预设，不是强制）

| 情况 | 推荐 |
|------|------|
| 短帖/论断，快速回应 | Workflow 1 |
| 完整技术文章或方案 | Workflow 2（默认） |
| 重要行业论断 / 主流方法论 | Workflow 3 |
| 只需确认某逻辑是否成立 | `01-dissect`（轻量）即可 |
| 只需跨领域解法，不要攻击文 | 停在 `03-other-mountains` |
| 正向建设，不是批判现有东西 | 走 `aolun-build`（不归 fileflow 拆解默认） |

## Part 4：checkpoint 与人话汇报（对齐 enloom v1.2）

**checkpoint = 阶段结束，不是暂停等待。**

1. **阶段结束就停：** 解剖完成（`01-dissect` 后）、扫描完成（`02-scan` 后）、进入攻击/整合前（`04-attack` 前与 `99-final` 前）各停一次。
2. **主窗口汇报后不派下一步。** 汇报完，本阶段即结束，不再自动派发后续步骤。
3. **用户没明确回复「继续 / 调整 / 停止」就什么也不做。沉默 ≠ 授权**，不得把自己的推荐当成人的决定。
4. **无人托管仅在用户明确授权时启用**，且只在授权覆盖的目标/范围/权限内连续推进；越过授权边界、或出现高风险/不可逆/扩大范围的变化，仍停下重新确认。
5. **阻塞型路线变化随时停**：subagent 回报扩大范围/高风险/不可逆/决定下游是否继续的项，立即停人；普通待决债先登记，到下一关键节点一并汇报。
6. **用户可随时打断**：「修改 / 跳过 / 结束 / 重新来」即生效。修改→带意见重派；跳过→标 `⊘跳过` 并在下一输出头部注明；结束→按 Part 6 就地收尾。

### 人话汇报（一屏读完）

```markdown
## 目标
一句话说本阶段要达成什么。

## 已完成
- 实际落盘的结果

## 现在到哪里
已完成什么、当前在什么阶段、后面还剩什么。

## 发现和债
- 新事实、偏离、未闭合问题及其影响

## 需要你决定
继续、调整还是停止；为什么现在需要决定。

## 我的建议
给一个明确建议和理由。
```

这是信息清单不是固定表单：空项省略，没有需要决定的内容时不制造问题。不用内部编号和 agent 术语代替事实。

## Part 5：`00-todolist.md` 格式与债区

### 00-todolist.md 格式

```markdown
# 任务根据地 — <brief>

> 创建时间：<yyyy-mm-dd HH:MM>
> 工作流：<Workflow 1/2/3>
> 授权模式：默认等人 / 无人托管

---

## 执行状态

| 步骤 | 状态 | 输出文件 | 摘要 |
|------|------|---------|------|
| 01-dissect | ⬜待执行 | 01-dissect.md | — |
| 02-scan | ⬜待执行 | 02-scan.md | — |
| 03-other-mountains | ⬜待执行 | 03-other-mountains.md | — |
| 04-attack | ⬜待执行 | 04-attack.md | — |

> 状态标记：⬜待执行 🔄当前 ✅完成 ⊘跳过

---

## 债 / 未闭合问题

> **登记不删行**：已闭合标 `✅` 保留原文，不静默覆盖；矛盾项显式标 `⚠矛盾`；放行项标 `已由用户/主窗口放行` 并保留原行。

| # | 类型 | 内容 | 来源步骤 | 状态 |
|---|------|------|---------|------|
| 1 | 新债 | <…> | 01-dissect | ⬜待处理 |

> 类型：`新债` / `路线变化` / `需主窗口决定` / `矛盾`。
> **同源 #N 去重**：认下新债时先与已有条目比对——同源/语义重复的不新增编号，在已有行追加 `同源 #<已有编号>` 或合并进已有行。登记不删行：归并/放行都用状态列标注，不静默删除。
> 无法确定是否重复时，宁可在已有行追加引用，也不新增独立编号。长任务可独立 `debt.md`，00-todolist 保留一行指向它。

---

## 原文索引
- 输入模式：<粘贴 / 快照 / 引用>
- 存储模式：<快照 / 引用>
- 源路径 / 单文件 / 源目录 / 索引入口 / 外部索引 / 总行数：按实际填
- 语义线索：<01-dissect 完成后由 subagent 追加关键位置索引>

---

## 搜索策略
<00-prep-meta.md 存在则读取；否则默认：定位核心声称 / 数据证据 / 关键术语>
```

### 债区规则要点

- **`00-todolist.md` 是唯一真相源**：状态、摘要、债区都以它为凭；subagent 只读它、不写它，债通过【债回报】上报由主 agent 认下登记。
- **登记不删行 + 同源 #N 去重**：只给真增量新编号；语义重复走 `同源 #N`；所有登记行不静默删除。
- 阻塞型需决定先按暂停处理；普通待决债先登记，到下一关键节点一并汇报。

---

## Part 6：整合规则（99-final）

**先决条件：** 本次整合要包含的步骤必须全部 `✅完成`（或用户明确确认的 `⊘跳过`）。用户「提前整合」时必须点名要包含哪些已完成步骤，未完成的只能跳过/留债，不得当作已包含。

1. 确认 slug（回车用 `<brief>`）。
2. 写入 `99-final-<slug>.md`：头部记整合时间（实际生成时刻，不早于任何包含步骤的输出时间）、任务目录、包含步骤列表；按序拼接各步骤完整内容；末尾附整体摘要与债区中仍 `⬜待处理 / ⬜需决定` 的条目（已闭合的不重复）。
3. 展示 `✓ 已生成：<路径>`。

**向下游传递：** 把 `99-final-<slug>.md` 路径传给任意下游 skill 即可作为完整分析文档使用。

---

## 不做

- 不写剧本、不铺背景、不穷举 corner case。
- 不重造 orchestrator、不并行派四维 subagent（归 `aolun-scan` 单文件）。
- 不把原文/上游内容塞进 subagent prompt（除非降级到内存模式）。
- 不在汇报后擅自派下一步；沉默不当作授权。
- 不改共享状态：`00-todolist.md` 由主 agent 单写，subagent 只通过【债回报】提议。
