# 文件持久化分析路由器

> "打持久战，要有根据地。"
> —— 毛泽东《论持久战》

长文本分析是持久战。没有根据地（文件落盘），中间态就会在 compact 中消失。

本 skill 的核心原则：

**主 agent 只做两件事：管 `00-todolist.md`、派发 subagent。**
**所有文本分析由 subagent 完成——subagent 自己从文件系统读原文、读上游输出。**
**主 agent 永远不把原文内容或上游输出内容塞进 prompt——只传文件路径，subagent 产出落盘。**

**统一只传路径派发（默认）：** subagent 一律只读文件路径、分析产出写入落盘文件，主 agent 只读落盘摘要。**内存模式（在 prompt 内直接传原文/产出）仅为无法落盘时的降级兜底**——例如宿主环境不允许写文件、或 subagent 无法读写文件系统时。一旦可落盘即回到路径派发；内存模式必须在 00-todolist.md 的原文索引中标注 `（内存模式）`，以便恢复时知道产出不在盘中。

## Part 1：启动阶段

收到输入文本后，依次完成：

### 1. 提取 brief

brief 提取（从输入前 50 字符生成任务目录名）规则见 `aolun-prepare-docs` Part 2，本处不重复。示例：`"大语言模型的 Scaling Law 已经触顶了吗？本文认为..."` → `da-yuyan-moxing-scaling-law`。

### 2. 检测已有文档准备结果

如果任务目录已存在且其中有 `00-prep-meta.md`：

1. 读取 `00-prep-meta.md` 的输入形态和存储模式
2. 向用户展示：`检测到已有的文档准备结果（<输入形态>，<存储模式>，<准备时间>）。`
3. 跳过文档准备步骤，直接进入创建 `00-todolist.md`（格式见 Part 4，从 `00-prep-meta.md` 读取搜索策略）
4. 继续执行崩溃恢复检测

如果没有 `00-prep-meta.md`，继续执行文档准备逻辑。

### 3. 创建任务目录和文档准备

**文档准备（brief 提取 / 任务目录创建 / 快照·引用 / 索引生成）以 `aolun-prepare-docs` 为唯一权威，此处不重复定义。** fileflow 只消费其结果或做最简内联兜底。`aolun-prepare-docs` 是 fileflow 的**可选前置**：

- **粘贴文本**：fileflow 可直接内联做最简准备（见下），也可先经 prepare-docs。
- **文件路径 / 目录路径输入**：优先提示用户先使用 `aolun-prepare-docs` 准备（生成 `00-prep-meta.md` / `00-index.md` / `00-original.md` 或 `00-sources/`），再进入 fileflow。若用户希望 fileflow 内联处理路径，按 prepare-docs 的目录结构约定执行。
- 若用户已用 prepare-docs 准备好任务目录，fileflow 只做第 2 步检测（`00-prep-meta.md` 存在）即可，不再重复准备。

**内联简化文档准备（最简兜底，仅覆盖没有 prepare-docs 的粘贴文本场景）：**

如果 `docs/aolun.skill/` 目录不存在，先创建它；再创建任务子目录 `docs/aolun.skill/<yyyy-mm-dd>-<brief>/`（brief 提取规则见 `aolun-prepare-docs`）。将原始输入文本保存为 `00-original.md`（纯原文，无 header 注释，第 1 行就是原文第 1 行）。

如果输入是文件路径或目录路径（而非粘贴文本），且 `00-prep-meta.md` 不存在：
```
提示用户："检测到路径输入但未找到文档准备结果。请先使用 aolun-prepare-docs 准备文档，或直接粘贴文本。"
终止当前流程。
```

创建根据地文件 `00-todolist.md`（格式见 Part 4）。**任务开始时主 agent 须记录本次运行模式**：在 `00-todolist.md` 头部写入 `> 授权模式：默认等人 / 无人托管`（与用户确认本次是「默认等人」——每到一个关键节点/需决定门停下来汇报等确认——还是「无人托管」——只按既定批次跑，不在节点等拍板）。默认取「默认等人」。如果 `00-prep-meta.md` 存在，从其搜索策略部分读取并填充 00-todolist.md 的搜索策略；否则使用默认搜索策略。

### 4. 崩溃恢复检测

如果 `docs/aolun.skill/<yyyy-mm-dd>-<brief>/00-todolist.md` 已存在：

1. 读取状态表
2. 找到第一个状态为 `⬜待执行` 的步骤
3. 告知用户：`检测到未完成的任务，从步骤 <NN>-<skill-name> 继续执行。是否继续？[继续] [从头开始]`
4. 继续 → 从该步骤恢复执行
5. 从头开始 → 清空任务目录后重建

> **旧任务目录兼容（不强制迁移）：** 历史任务目录可能只含 `00-prep-meta.md`、`00-todolist.md`、`00-original.md`、`00-index.md`、`00-sources/` 或编号中间文件（如 `01-dissect-concept.md`），未必有本节新增的「债/未闭合问题」区。这些旧目录仍**可读、可恢复**：fileflow 照常读取 `00-todolist.md` 状态表 / `00-prep-meta.md` 索引继续执行；缺失的债区不阻塞恢复——主 agent 在恢复时把旧目录中「未闭合/待验证/矛盾」线索就地补记进债区即可。**不要求、也不鼓励把旧任务目录一次性迁移到新格式。**

### 5. 询问工作流

展示以下选择，等待用户回复：

```
即将开始文件持久化分析。请选择工作流：

[1] Workflow 1 快速狙击（仅落盘）
    概念解剖 → 逻辑扫描 → 攻击文（50-200字）
    适合：只需要快速定位主要弱点，不做全面拆解

[2] Workflow 2 标准拆解（推荐）
    四层解剖 → 并行扫描 → 可选他山之石 → 攻击文
    适合：一篇完整的技术文章或方案

[3] Workflow 3 底朝天全拆
    同上，但扫描后增加深度验证轮次
    适合：重要行业论断或主流方法论

任务目录已创建：docs/aolun.skill/<yyyy-mm-dd>-<brief>/
```

### 6. 展示执行计划

根据用户选择，展示步骤序列（见 Part 3），等待用户确认开始。

## Part 2：逐步执行规则

### 核心架构

```
主 agent（fileflow 编排器）
  ├── 管理唯一真相源：00-todolist.md（含状态表 + 债/未闭合问题区）
  ├── 派发 subagent（只传文件路径，不传文本内容）
  ├── 从输出文件提取【摘要】块与【债回报】展示给用户
  ├── 在批次/关键节点暂停等人，平时连续推进
  └── 认下/打回 subagent 上报的新债，更新债区

subagent（每个分析步骤）
  ├── 自己用 Read/Grep 工具读原始文件
  ├── 自己用 Read 工具读上游输出文件（按需）
  ├── 自己用 Read 工具读 00-todolist.md 获取索引、搜索策略、债区
  ├── 执行 skill 分析（按五段式任务卡对齐目标）
  └── 将完整输出（含【摘要】+【债回报】）写入指定文件路径
```

**禁止：** 主 agent 将原文段落、上游输出内容复制进 subagent prompt（除非降级到内存模式）。

**允许：** 主 agent 将文件路径、搜索策略、任务指令写进 subagent prompt。

### 每步执行流程

**节奏：批次连续推进 + 关键节点暂停。** 不逐步骤停下等人，而是把一个批次内的步骤连续跑完，只在批次/关键节点边界停下来向用户汇报并等人决定（见「批次/关键节点暂停」）。用户随时可打断、修改、跳过、提前结束。

```
① 更新 00-todolist.md 状态表：当前步骤标记为 🔄当前

② 派发 subagent，prompt 骨架（五段式最小任务卡 + 路径 + 指令 + 债回报）：

你是 aolun 分析管线的一环。执行 <skill-name> 分析。

   【正目标】
   本步骤要交付什么（单一可验收产出）：<按 skill 定义的本步骤核心结果>

   【负目标】
   明确不做 / 不该出现：<不越出本层、不覆盖他人产出、不臆造证据、不写无引用结论>

   【边界】
   输入只读以下文件路径（只传路径，不塞原文）：
    - 原始文件：<00-original.md 或源文件路径>
    - 索引与状态：<00-todolist.md 的完整路径>
    - 索引入口：<00-index.md 的完整路径>（目录模式）
    - 上游输出：<上一步输出文件路径>（第一步无此项）
   输出写入：<当前步骤输出文件的完整路径>
   （路径分支 A/B/C 判定见 00-todolist.md 或 00-prep-meta.md 的输入模式）

   【够好】
   验收标准：<本层核心清单达成、证据带行号+直接引用、未找到已声明、产出落盘且含【摘要】>

   【尚不知道】
   明确写出你还不知道/无法验证的点，不要假装知道；这些进入【债回报】。

   【执行指令】
   1. 先读 00-todolist.md 的"原文索引""搜索策略""债/未闭合问题"部分
   2. 用 Read/Grep 直接搜索原始文件找关键证据；每个弱点必须附原文行号和直接引用
   3. 需要时 Read 上游输出文件；按 <skill-name> 的 SKILL.md 执行完整分析
   4. 将完整输出写入：<当前步骤输出文件的完整路径>

   【输出格式】
   文件顶部必须含【摘要】块（3-5 行核心判断），
   然后 --- 分隔线，然后完整分析内容（引用格式见 00-todolist.md 或 aolun-prepare-docs）。

   【债回报】（subagent 必须回报，可并入输出文件末尾）
   - 新债：本步骤发现但未解决/未验证的问题
   - 路线变化：本步骤结果是否偏离了原计划，需要主窗口重新决定
   - 需要主窗口决定：任何你不能自行拍板、需要人/主 agent 判断的点
```

**内存模式降级（仅当无法落盘时）：** 上述「路径 + 落盘」是默认。若宿主不允许 subagent 写文件/读文件系统，才允许把原文或产出塞进 prompt（内存模式），并在 00-todolist.md 标注 `（内存模式）`；否则一律按路径派发。

```
③ 等待 subagent 完成

④ 从输出文件提取【摘要】块（3-5行）与【债回报】

⑤ 更新 00-todolist.md：
   - 状态表：当前步骤标记为 ✅完成
   - 摘要列：写入提取的摘要
   - 债/未闭合问题区：认下 subagent 的新债（见 Part 4 债区规则，认下时**先去重归并**；若含「阻塞型需决定/关键路线变化」，先按 P1 门禁暂停；普通需决定先登记，到下一个关键节点再一并汇报）

⑥ 如果是 01-dissect-concept 步骤，额外操作：
   读 01 输出文件，提取概念层发现的关键位置信息，
   追加到 00-todolist.md 的"语义线索"部分

⑦ 在对话中展示摘要（不展示全文）

⑧ 是否暂停由「批次/关键节点暂停」规则决定，不是每步都停（见下节）。
```

### 批次/关键节点暂停（替代原"每步暂停"）

**默认：批次内连续执行，不逐步骤停下。** 仅在以下批次/关键节点停下来，用**人话一屏汇报**（一句进展 + 需要你决定 + 我的建议）并等人：

1. **解剖批次完成**（Workflow 2/3：`04-dissect-interest` 后）——四层解剖全部落盘，汇报各层摘要与整体判断，等确认再进入扫描。
2. **扫描批次完成**（`05-scan-summary` 后）——四维扫描综合完成，汇报主要弱点，等确认再决定是否引入他山之石/进入攻击。
3. **进入攻击/整合前**（`07-attack` 前、以及生成 `99-final` 前）——确认可发布口径与是否整合。
4. **关键路线变化 / 阻塞型需决定时**——subagent 回报「关键路线变化（扩大范围/高风险/不可逆）」或「阻塞型需决定」时，立即暂停；普通需决定债先登记，到下一个关键节点再一并汇报。
5. **Workflow 1**：因其步骤少，可在 `02-scan-logic` 后暂停一次即可。

#### 关键决定门禁（P1）

> 不是每个「需要主窗口决定」都要立刻停下。只有**关键判断点**才默认必须等人；普通待决债先挂起，在下一个关键节点统一汇报。

**阻塞型（必须立即暂停，默认等人）：**
- 路线变化会扩大范围、提高风险或不可逆（例如改攻击对象、授权读取外部资料、进入发布/整合）。
- 当前步骤的结论会直接决定下游是否继续（例如是否进入攻击、是否引入跨领域解法、是否生成 final）。
- 用户/主窗口明确标记为“必须现在拍板”的事项。

**普通待决债（先登记，不阻断当前批次）：**
- 事实性待验证、口径待确认、不影响下一步执行方向的「需要主窗口决定」。
- 记录到债区，继续当前批次；到下一个关键节点（解剖完成/扫描完成/进入攻击前/整合前）时，把所有待决债一屏列出等人拍板。
- 若后续某一步依赖该决定才能继续，则自动升级为阻塞型并立即暂停。

执行规则：

1. 收到「阻塞型需决定/关键路线变化」后，**停留在当前批次**，用一屏人话汇报：该决定点是什么、我的建议、需要你决定什么。
2. 收到「普通待决债」时，**不打断当前批次**，登记进债区并在下一个关键节点汇报；如果该债升级为阻塞型，按第 1 条处理。
3. **在阻塞型决定获显式放行前，不派发依赖它的下一步 subagent。** 若授权模式为「无人托管」，跳过本暂停继续既定批次（但须在债区注明「无人托管放行」）。
4. 放行后，在债区把对应条目状态**写为「已由用户/主窗口放行」**（保留原行、不静默删除；可追加 `> 放行：<用户决定内容>` 一行）。
5. 若用户打回/改向，则按「修改时」规则重新派发，并把打回结论写回债区。

**任何时刻用户可随时打断：** 用户说「修改/跳过/结束/重新来」即生效，无需等批次边界。

**修改时：** 重新派发 subagent（将用户修改意见作为附加指令传入），覆盖写入文件，再次展示摘要，回到所在批次继续。

**跳过时：** 在 00-todolist.md 状态表中标记为 ⊘跳过，在下一个输出文件头部注释中记录 `> 注：<NN>-<skill-name> 已跳过`，继续执行下一步（若跳过的步骤是关键决策门，仍应暂停汇报一次）。

**提前整合 / 结束：** 用户选择提前整合或停止时，按 Part 5 生成 `99-final` 或就地收尾，并把未完成步骤与债记入债区供后续恢复。

### 01-dissect-concept 特殊处理

概念层解剖是唯一需要建立全局理解的步骤。派发 prompt 中追加：

```
【概念层特别指令】
这是第一步分析，你需要建立对文章的全局理解。
请使用 Read 工具完整阅读原始文件（可分段读取）。
概念层的目标是回答"这东西声称自己是什么"——必须看全貌。
完成分析后，在 00-todolist.md 的"语义线索"部分追加你发现的关键位置索引。
```
